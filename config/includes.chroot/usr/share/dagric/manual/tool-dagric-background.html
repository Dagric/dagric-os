Helpers that run by themselves

The nine small things Dagric does without asking, what each one is, and how to stop it.

On Windows this wasthe Windows first-run experience and OEM startup apps

What it is

Almost everything on this machine waits to be asked. Nine helpers do not, and it is only fair to name all nine. Five are one-shot: each retires itself once it has done its job. Four stay, and each of those says below why.

  • dagric-firstrun — the setup wizard at your first login. It records that it has run when the window is genuinely on screen, so a login where the desktop was not yet ready does not waste its one chance.
  • dagric-brand-launcher — puts the Dagric logo on the launcher button. It changes the icon and nothing else, and if it cannot find the launcher this session it leaves itself in place to try again next time.
  • dagric-driver-offer — on the first login only, if this machine has an NVIDIA card and no driver installed, it offers to run the driver helper. On any other machine it exits silently.
  • dagric-snapshot-setup — runs once on the first boot of an installed system to configure snapshot recovery. On a non-btrfs install it does nothing and stands down.
  • dagric-pdf-queue — a one-time service that creates the printer called PDF on the first boot, so that Print to PDF is there the first time you look for it. It stamps itself done only if it succeeded, so on an installed machine it runs exactly once.
  • Dagric display defaults (/usr/lib/dagric/display-autoscale) — stays. It runs at every login, not only the first. It measures your screen and picks a sensible text size, and it puts back a size that Dagric Display was interrupted in the middle of changing. It stays because a monitor plugged in later needs measuring too, and because a bad size survives a reboot unless something undoes it.
  • Dagric accessible boot (/usr/lib/dagric/a11y-live) — stays. At every login it reads one line of /proc/cmdline and exits immediately unless this machine was started from the accessible boot entry, in which case it turns on Orca. An installed system never carries that flag, so there it does nothing at all.
  • Dagric desktop shortcuts (/usr/lib/dagric/desktop-shortcut-trust) — stays, and it is the one helper that keeps running for the whole session. It watches your Desktop folder so that dragging a program out of the launcher makes a shortcut that works, the way it did on Windows. It marks a file runnable only when that file is byte-for-byte identical to a launcher already installed on this machine, so a .desktop file you downloaded still gets KDE's warning.
  • dagric-ssh-hostkeys PRO — stays. It runs at every boot and does nothing on almost all of them: it generates this machine's own SSH host keys if they are missing, so that no two Dagric machines share one identity. The free edition has no SSH server, so there it never runs.

One more, dagric-app-names, is neither an Autostart entry nor a service: it runs at build time and again after package operations. It never asks anything and never touches your files; it is what makes the launcher say Files instead of Dolphin — see why the apps have plain names.

Five things you will actually do

  1. See what starts with your session

    System Settings → Autostart, or look straight in ~/.config/autostart/ — the six Autostart entries above are the files in there, and you may delete any of them. The other three are system services rather than session items; systemctl list-unit-files 'dagric-*' lists those.

  2. Open the welcome page again

    The short written account of what Dagric is lives at /usr/share/dagric/welcome/index.html. Reach it with dagric-welcome, or from the Dagric Hub's Welcome guide row. It is no longer the first-run experience — the setup wizard is — because a browser tab cannot set your wallpaper or fetch your files.

  3. Refuse the driver offer permanently

    Answer no. It removes its own autostart entry before it even asks, so it will not ask twice. You can still run sudo dagric-drivers whenever you like.

  4. Put the launcher icon back to stock

    Right-click the launcher button → Configure, and choose a different icon. Nothing will change it back.

  5. Check snapshot setup worked

    sudo snapper -c root list should show a baseline snapshot taken at your first boot. If the list is empty and your disk is btrfs, sudo dagric-snapshot-setup runs it again.

One thing that will surprise you

That is the complete list. Nine small helpers, five that retire themselves and four that stay for the reason each gives above, and none of which sends anything anywhere. There is no updater service, no telemetry agent, no vendor assistant, no registration reminder and no trial countdown. Six of the nine are Autostart entries — all of the above except the snapshot, Print-to-PDF and SSH host-key services, which are one-time system jobs. If you find anything else in Autostart, you or an application you installed put it there.

Where to find it

System Settings → Autostart. The scripts themselves are in /usr/bin/ and can all be run by hand.
