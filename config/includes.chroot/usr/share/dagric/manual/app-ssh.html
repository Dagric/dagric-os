SSHPRO

Reaching other machines, and letting other machines reach this one — carefully.

On Windows this wasPuTTY, and Windows OpenSSH
This one is part of Dagric OS Pro. You are reading the manual on the free edition, so it is not installed on this computer. The page is here on purpose — you should be able to see exactly what Pro adds before you decide whether you want it.

What it is

The SSH client is installed and ready: ssh user@host and you are on another machine.

The SSH server is installed too, and it is deliberately off, and its port is closed in the firewall. Turning it on is a two-step decision you make on purpose. Dagric also ships a hardened configuration in advance, so that if you ever do enable it, it starts with root login refused, three authentication attempts, and X11 forwarding disabled — rather than at stock defaults.

Five things you will actually do

  1. Connect to a server

    ssh user@example.com. The first connection shows a fingerprint and asks you to confirm; that is the moment you are meant to check it, because it is what protects you from being redirected to somebody else's machine.

  2. Log in without a password

    ssh-copy-id user@example.com installs your public key on the server. Afterwards the connection uses the key. This is both more convenient and considerably more secure than a password.

  3. Copy files

    scp file user@host:/path/, or rsync -av folder/ user@host:/path/ for something resumable. In Dolphin, press Ctrl+L and type sftp://user@host to browse a server as if it were a folder.

  4. Save yourself typing

    Put hosts in ~/.ssh/config with a short alias, a user name and a key file, and then ssh myserver is enough.

  5. Enable the server on this machine

    Both halves are required: sudo systemctl enable --now ssh and then sudo firewall-cmd --permanent --add-service=ssh followed by sudo firewall-cmd --reload. If you skip the second, nothing can reach it — which is exactly how it ships.

One thing that will surprise you

Nothing is listening on this machine until you say so. Installing an SSH server on most systems means it starts immediately, on every network, accepting passwords. Dagric refuses that on your behalf: the service is disabled and the firewall closed, and the hardened configuration is already in place for the day you turn it on. If you were expecting to be able to SSH in after installing, this is why you cannot.

Where to find it

A terminal. Server status: systemctl status ssh.
