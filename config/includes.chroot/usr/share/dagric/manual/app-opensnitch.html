System and safety

OpenSnitchPRO

See — and control — every outbound connection any program makes.

On Windows this wasLittle Snitch, GlassWire
This one is part of Dagric OS Pro. You are reading the manual on the free edition, so it is not installed on this computer. The page is here on purpose — you should be able to see exactly what Pro adds before you decide whether you want it.

What it is

An ordinary firewall controls what can reach in. OpenSnitch controls what can go out: it watches every connection a program tries to make and can ask you, per application, whether to allow it.

It is the single most revealing tool on the machine. Run it for an afternoon and you will find out exactly which of your programs talk to the internet, how often, and to whom.

Five things you will actually do

  1. Answer the first question about each program

    Dagric starts with an allow-by-default policy. Existing deny rules still block matching traffic. With an administrator's interface connected, OpenSnitch can ask the first time a program reaches the internet. Dagric answers in advance for its own background services (the clock, updates, printing, the software centre), so the questions you get should be about programs you chose to run. Those pre-answers live in /etc/opensnitchd/rules as one small file each; delete one and you will be asked about that program again.

    If you walk away, the answer is yes. The dialog counts down, and when it runs out Dagric allows the connection rather than blocking it. That is a deliberate change from the OpenSnitch default, which is to deny: a program cut off by a dialog nobody saw is the hardest kind of fault to trace back, and it contradicted the promise above. Once you switch the machine to deny-by-default (below), you are choosing the stricter behaviour knowingly, and the countdown follows suit.

  2. See what has been happening

    Open the OpenSnitch UI from the tray. The tabs list connections by application, by host and by port, with counts. Sort by application and read down the list.

  3. Choose what happens without an answer

    Two separate settings, in two separate places, and it is worth knowing which is which. In Preferences → UI, Default action is what the countdown does when you do not answer — Dagric ships it as allow; set it to deny and an unanswered dialog blocks. In Preferences → Nodes, the daemon's own default action and intercept unknown connections govern what happens when the daemon cannot reach this window at all. Review both settings before choosing a stricter policy; changing one does not change the other.

  4. Write a rule

    Rules can be as broad as “allow this application anywhere” or as narrow as “allow only to this host on port 443”, and can expire after a set time. Blocking a single telemetry endpoint while leaving an application otherwise working is entirely possible.

  5. Back out safely

    If a rule breaks something, set the default action back to allow in the UI. Nothing is permanent and the daemon can be stopped with sudo systemctl stop opensnitch.

One thing that will surprise you

The first hour is uncomfortable. Once you turn prompting on you discover how much perfectly ordinary software connects to perfectly ordinary places — update checks, certificate revocation lists, time servers, font downloads — and the temptation is to block everything and then spend the evening wondering why the browser is broken. Allow the things you recognise, take your time, and remember that on a Dagric machine you started from a far quieter baseline than you are used to.

Where to find it

The OpenSnitch icon in the system tray, or launcher → OpenSnitch. The daemon starts with the system; the window is just a view onto it.

Not while you are trying Dagric from the USB stick. In the live session the firewall is deliberately switched off and its tray icon hidden, so it cannot interrupt the installer — which fetches packages as a program OpenSnitch has never seen before, at a moment when nobody is necessarily watching the screen. It switches itself on the first time the machine starts from its own disk. Nothing to turn on, and nothing you learn from the USB session would have been kept anyway.

Who can manage it

OpenSnitch changes network rules for the whole computer, so Dagric lets only administrator accounts in the sudo group open its interface. The main account created by the installer belongs to this group. Open it normally from your desktop, never with sudo.

A standard account cannot create the control socket or receive its own rule prompts. Existing OpenSnitch rules and the separate system firewall still apply. If no administrator's interface is connected, new unmatched connections follow the daemon's configured default — initially allow. Closing the window is not the same as blocking all network access.

All administrator accounts share the same machine-wide policy. One connected interface should manage it at a time; do not treat separate administrator sessions as independent firewalls.

The managed launcher and daemon use /run/dagric-opensnitch/osui.sock. The directory is recreated at boot for root and sudo administrators only. The launcher refuses unsafe permissions instead of falling back to a public temporary directory. Custom remote or TLS UI settings are not used by this managed local launcher.

After a Dagric tools update: save your work, then sign out and back in (or restart) so any older running interface is replaced. If the launcher reports a directory or package problem, ask an administrator to repair the package; do not loosen the directory permissions. Existing personal preferences are preserved. A missing initial prompt preference is written only by your own account.
