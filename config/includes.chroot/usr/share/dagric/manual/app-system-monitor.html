System Monitor

What is running, what is slow, and how to stop something that has hung.

On Windows this wasTask Manager

What it is

System Monitor is the task manager — the launcher calls it exactly that — and Ctrl+Shift+Esc opens it. Dagric binds that key deliberately: it is pure muscle memory for Windows users, and pressing it and landing on nothing is a bad first impression. KDE's own Meta+Esc still works too.

It shows CPU, memory, disk and network use over time, and a list of running applications and processes that you can sort by whatever is eating the machine.

Five things you will actually do

  1. Force-quit an app that has stopped responding

    Find it in the Applications page, select it, press End. If it will not go, use Kill from the right-click menu.

  2. Find out what is making the fan spin

    Sort the process list by CPU, descending. The top row is the culprit. Do the same with Memory when the machine starts swapping and everything goes treacly.

  3. Check whether you are short of RAM

    The Overview page shows memory in use versus total. Dagric also enables compressed swap, so a machine with 4 GB copes noticeably better than the raw number suggests.

  4. See what is using the network

    The History page charts network throughput. The process list can add per-process network columns from the column header's right-click menu.

  5. Kill a frozen window instantly

    Ctrl+Alt+Esc turns the mouse pointer into a skull; click the offending window and it dies. Press Esc to cancel without clicking anything.

One thing that will surprise you

The numbers add up differently to Windows. Linux deliberately uses spare RAM as disk cache, so “memory used” often looks alarmingly high on a machine that is perfectly happy. The figure to watch is swap: if swap use is climbing and the disk is thrashing, you are genuinely short of memory. Cache is not.

Where to find it

Ctrl+Shift+Esc (or Meta+Esc), or launcher → Task Manager (also found by typing taskmgr or System Monitor).
