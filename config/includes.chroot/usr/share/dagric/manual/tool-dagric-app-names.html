Why the apps have plain names

Your menu says Files, Photos and Terminal. Forum posts say Dolphin, Gwenview and Konsole. Both are right.

On Windows this wasnothing — this is Dagric solving a Linux problem

What it is

Open a stock KDE launcher and you are offered Dolphin, Konsole, Gwenview, Okular, Ark, Elisa, Kate and Spectacle. Not one of those words tells you what the program does. Dagric renames them for the job:

  • Dolphin → Files, Konsole → Terminal, Gwenview → Photos, Okular → Document Viewer, Ark → Archive Manager, Kate → Text Editor, Elisa → Music, mpv → Videos.
  • Spectacle → Screenshot, Discover → Software Store, KCalc → Calculator, System Monitor → Task Manager, KWallet → Saved Passwords, Skanlite → Scanner, GDebi → Package Installer.
  • On Pro: Filelight → Disk Space, KDE Connect → Connect Your Phone, Timeshift → System Restore, Vorta → Encrypted Backup, BleachBit → Disk Cleanup.

Firefox, LibreOffice, GIMP, Blender, Krita, Inkscape, OBS, Thunderbird, KeePassXC, Audacity, HandBrake and qBittorrent keep their own names — those brands are what you already know and search for.

Five things you will actually do

  1. Search by either name

    Typing Dolphin finds Files, and typing File Explorer finds it too. Every renamed app keeps its original name as a search keyword, along with the Windows name and the common misspellings — notepad++, taskmgr, prtscn, this pc.

  2. Read the second line in the menu

    Under each name the launcher shows what it is and, in brackets, what it is really called: File manager (Dolphin). So the menu agrees with the window title bar rather than contradicting it.

  3. Follow a guide written for KDE

    A forum post saying “open Dolphin and press F4” still works. The program is unchanged; only its label in the menu is ours. That is why both names appear on every page of this manual.

  4. Understand the window titles

    Title bars still say Dolphin, Konsole, Gwenview. No menu entry can change what a program calls its own window, and Dagric would rather show you the real name there than pretend.

  5. Get the original names back

    The renames live in /usr/local/share/applications as complete overriding copies. Delete them and the upstream names return at once. Note that they are regenerated after package operations, so an administrator who wants them gone permanently should remove the apt hook too.

One thing that will surprise you

The rename survives updates, which is the whole difficulty. The obvious approach — editing the menu entries KDE installs — works until the next KDE update, at which point the package manager restores the original file and “Files” silently becomes “Dolphin” again on a machine whose owner has no idea why. A rename that expires is worse than no rename. So Dagric writes complete overriding copies into a directory the package manager never touches, and regenerates them after every package operation from whatever upstream currently ships.

One honest limit: the renames apply to English installs. Install in German or French and the menu keeps the translated upstream names, because throwing away real translations to impose English labels would be a worse trade.

Where to find it

Nowhere — it runs at build time and after package operations. The generated files are in /usr/local/share/applications.
