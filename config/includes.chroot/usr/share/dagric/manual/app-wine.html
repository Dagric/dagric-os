WinePRO

Run Windows programs directly, with no Windows underneath.

On Windows this wasWindows itself, for a lot of software
This one is part of Dagric OS Pro. You are reading the manual on the free edition, so it is not installed on this computer. The page is here on purpose — you should be able to see exactly what Pro adds before you decide whether you want it.

What it is

Wine is not an emulator: it reimplements the Windows programming interfaces on Linux, so a Windows program's instructions run directly on your processor. That means near-native speed, and it means compatibility varies by program rather than by category.

Dagric OS Pro installs both the 64-bit and 32-bit halves, so the classic thirty-year back catalogue of small Windows utilities runs as well as modern software.

Five things you will actually do

  1. Run a program

    wine setup.exe in a terminal, or right-click the file in Dolphin → Open With → Wine Windows Program Loader. Installed programs land in ~/.wine/drive_c/Program Files and usually get a launcher entry.

  2. Configure the fake Windows

    winecfg opens a control panel: which Windows version to claim to be, drive mappings, graphics options, audio. Claiming an older Windows version fixes a surprising number of installers.

  3. Add the missing pieces

    winetricks installs the runtimes programs expect — the Visual C++ redistributables, .NET, DirectX components, core fonts. When a program complains about a missing DLL, this is the tool.

  4. Keep programs apart

    Give each application its own prefix: WINEPREFIX=~/.wine-appname wine setup.exe. One program's requirements then cannot break another's. Bottles does exactly this with a window instead of environment variables, and is the easier route.

  5. Find out if your program works

    The Wine Application Database at appdb.winehq.org rates thousands of programs and lists what people had to do. Check before you spend an evening.

One thing that will surprise you

It is often not slower — and occasionally it is faster. Because Wine translates calls rather than emulating hardware, a Windows program under Wine on Linux sometimes outperforms the same program on Windows on the same machine. It is not magic and it is not universal, but the instinct that “compatibility layer” must mean “slow” is simply wrong.

What does fail: anything with kernel drivers, most anti-cheat, and software that checks the hardware very closely. For those, use a real Windows in a virtual machine.

Where to find it

A terminal, or right-clicking a .exe. Configuration: winecfg and winetricks.
